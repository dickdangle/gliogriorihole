Yes. The clean model is:

- `engine NFT`: immutable-ish ruleset identity
- `state NFT`: revisioned play state / save artifact
- `state NFT -> engine NFT`: explicit reference

The `engine NFT` holds the conceptual rule layer:
- ruleset name
- schema version
- player guide URI
- rule book URI
- engine code / spec hash
- allowed state schema versions

The `state NFT` holds run-specific provenance:
- state snapshot hash
- revision number
- previous revision hash
- engine NFT reference
- content URI for the full save state

That avoids rebuilding the system every time because the engine layer is stable and the state layer just advances by rev.
